# IE4060 — TurtleBot3 Burger Autonomous Maze Navigation (ROS 2 Jazzy)

**Target:** Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic + RViz2. Designed for the Figure 1 6×6 maze (0.5 m grid), TurtleBot3 Burger and Nav2. The project is a proper `ament_python` ROS 2 package named **`ie4060_maze`**.

> Important distinction: `maps/maze.pgm` is an **ideal/reference map synthesized from the Gazebo wall geometry**, NOT a map measured by SLAM. For the assignment's SLAM evidence, create and submit your real saved SLAM `maze.pgm` + `maze.yaml` separately. The DQN experiment is an **offline 6×6 cell-level environment**, NOT a Gazebo motor controller. A live Gazebo DQN policy would need additional work; never claim these offline metrics are physical simulation results.

## 1. Prerequisites

You said ROS Jazzy, Gazebo Harmonic and `turtlebot3_gazebo` are **already working** in `~/ie4060_ws`. Install any missing apt dependencies:

```bash
sudo apt update
sudo apt install -y \
  python3-numpy python3-yaml python3-colcon-common-extensions \
  ros-jazzy-ros-gz ros-jazzy-turtlebot3-navigation2 \
  ros-jazzy-navigation2 ros-jazzy-nav2-bringup \
  ros-jazzy-slam-toolbox ros-jazzy-nav2-map-server \
  ros-jazzy-turtlebot3-teleop ros-jazzy-tf2-ros
```

If needed, install the official Gazebo simulation package, which must be built in your **same workspace**:

```bash
cd ~/ie4060_ws/src
# Only if the folder is not there already:
git clone -b jazzy https://github.com/ROBOTIS-GIT/turtlebot3_simulations.git
cd ~/ie4060_ws
colcon build --symlink-install --packages-select turtlebot3_gazebo
```

## 2. Install this project into the ROS workspace

If the ZIP downloaded into **Ubuntu VM** `~/Downloads`, run:

```bash
mkdir -p ~/ie4060_ws/src
unzip -o ~/Downloads/IE4060_TurtleBot3_Runnable_Project.zip -d ~/ie4060_ws/src/
cd ~/ie4060_ws/src/IE4060-TurtleBot3-Autonomous-Navigation
bash scripts/install_project.sh
```

The installer reads your installed `/opt/ros/jazzy/share/turtlebot3_navigation2/param/burger.yaml` and SLAM Toolbox YAML and creates **complete, version-matched** `config/nav2_params.yaml` and `config/slam_params.yaml`. It also generates the reference map and builds the ROS package. The small config files inside the ZIP are pre-install markers; **do not launch until install_project.sh finishes**.

If the package path does not resolve, open a fresh terminal and run:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ie4060_ws/install/setup.bash
ros2 pkg prefix ie4060_maze
```

**Don't simultaneously run your old Stage 2 Gazebo/robot processes** with these launch files, or you will get duplicates. Always set the robot model in every new terminal:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ie4060_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
```

Wait for the robot to spawn near `x=-1.25, y=1.25` and the simulator to start running. This launch includes official ROBOTIS Gazebo spawning, bridge and robot_state_publisher.


## 5. Option B — Autonomous navigation — Terminal B

Use the included **geometry reference map** for a first end-to-end Nav2 test:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ie4060_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
ros2 launch ie4060_maze navigation.launch.py
```

This starts the normal TurtleBot3 Nav2 stack and RViz2. For the supplied reference map, `prepare_configs.py` defaults to AMCL `set_initial_pose: true` with the reference spawn pose, so it should know where the robot starts. If not, or if you moved the robot, select **2D Pose Estimate** in RViz2, point the arrow in the direction the robot faces and wait for `map -> base_link` to appear. Use **Nav2 Goal** to click in a **white free corridor**, not a wall or unknown region.

To use **your REAL Stage 3 SLAM map** instead of the reference map, configure manual initial pose, because a SLAM map's origin may differ:

```bash
# Stop Nav2, but retain Gazebo. Go to your source checkout:
cd ~/ie4060_ws/src/IE4060-TurtleBot3-Autonomous-Navigation
python3 scripts/prepare_configs.py --initial-pose rviz
cd ~/ie4060_ws
colcon build --symlink-install --packages-select ie4060_maze
source install/setup.bash
ros2 launch ie4060_maze navigation.launch.py \
  map:=$HOME/ie4060_ws/maps/maze.yaml
```

Then click 2D Pose Estimate **in the coordinate system of the saved SLAM map**. Mapping may be incomplete: if a goal is in gray/unexplored space, Nav2 may be unable to plan to it. Re-map fully if necessary.

For diagnostic outputs, in a sourced terminal:

```bash
bash ~/ie4060_ws/src/IE4060-TurtleBot3-Autonomous-Navigation/scripts/doctor.sh
```

Watch for `/planner_server: active [3]`, `/bt_navigator: active [3]`, and correct `/cmd_vel` endpoint types. If startup stops, copy **the first `planner_server`, `global_costmap`, or lifecycle-manager ERROR from the Nav2 terminal**. Never publish a fake static `map -> odom` transform. Check current map TF and costmap before making tuning changes.

## 6. Collect real Gazebo/Nav2 navigation results

Run *before* clicking the first goal, in another terminal:

```bash

source ~/ie4060_ws/install/setup.bash
ros2 run ie4060_maze goal_metrics --ros-args -p use_sim_time:=true
```

For each RViz clicked goal, the logger listens to Nav2 action status and `/odom`, then appends **simulation-clock time and traveled odometry path length** to `~/ie4060_ws/results/nav2_runs.csv` upon completion. Check if the actual robot collides in Gazebo and record that yourself (it is **not** measured by this logger). Log at least **three different clicked goals** for the VIVA. For consistent comparison, use the same start pose each time and record success/failure.

## 7. Deep Q-Learning experiment (runs offline with only NumPy)

DQN is trained on **36 discrete maze cells with four actions**, walls parsed from the same `worlds/maze.world`. This is a genuine trainable, goal-conditioned neural Q-function, using replay memory, a target network and epsilon-greedy exploration. It is not a LiDAR policy or direct Gazebo actuator controller.

From the root folder:

```bash
cd ~/ie4060_ws/src/IE4060-TurtleBot3-Autonomous-Navigation
python3 -m unittest discover -s tests -v
python3 -m dqn.evaluate  # pretrained reference checkpoint included
python3 -m dqn.train --episodes 3000  # train own model on CPU; slower in VMware
python3 -m dqn.evaluate  # evaluate freshly trained checkpoint
```

Evaluation creates `results/grid_comparison.csv` with success, discrete path length, invalid movements and shortest-path efficiency for three selected grid goals. The included pretrained model was trained with seed 7 for 3000 offline episodes. It is a baseline: reproduce your own evaluation and do not report it as real Gazebo traversal time.

**Assignment DQN limitation:** The PDF asks for a Deep Q-Learning approach. This project provides a runnable DQN experiment and comparison, but a full learning-based navigation controller in Gazebo requires translating grid actions to safe motion control, pose feedback, and collision detection, plus retraining/testing. Do not claim that the offline policy controls TurtleBot3 in Gazebo.
